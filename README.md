# payment

결제(Payment) 기능을 중심으로 한 웹 서비스 프로젝트입니다.
프론트엔드와 백엔드를 하나의 저장소에서 함께 관리하는 **모노레포** 구조로 운영합니다.

## 데모

![demo](./assets/demo.gif)

## 프로젝트 개요

- 사용자가 상품을 주문하고 결제할 수 있는 서비스를 구현합니다.
- 프론트엔드는 주문·결제 화면과 결제 결과 화면을 제공합니다.
- 백엔드는 주문 생성, 결제 요청/승인/취소, 결제 내역 관리 API를 제공합니다.
- 결제 데이터는 MySQL에 저장하며, 결제 금액과 상태는 반드시 서버에서 검증합니다.

## 저장소 구조

```
payment/
├── frontend/      # 프론트엔드 애플리케이션 (주문·결제 UI)
├── backend/       # 백엔드 API 서버 (주문·결제 도메인, DB 연동)
├── .gitignore
└── README.md
```

각 디렉터리에는 별도의 `README.md`를 두어 실행 방법과 세부 구조를 설명합니다.

## 기술 스택

| 구분     | 기술      | 비고                             |
| -------- | --------- | -------------------------------- |
| Frontend | 미정      | `frontend/README.md`에 기재 예정 |
| Backend  | 미정      | `backend/README.md`에 기재 예정  |
| Database | MySQL 8.4 | 로컬 `localhost:3306`            |

## 결제 흐름 (개요)

```
[사용자] ──주문──▶ [Frontend] ──주문 생성 요청──▶ [Backend] ──저장──▶ [MySQL]
                       │                              │
                       │◀──── 주문번호·결제 금액 ──────┘
                       │
                       ├──결제 요청──▶ [PG사]
                       │                 │
                       │◀── 인증 결과 ────┘
                       │
                       └──승인 요청──▶ [Backend] ──금액 검증·승인──▶ [PG사]
                                          │
                                          └── 결제 상태 갱신 ──▶ [MySQL]
```

1. 사용자가 상품을 선택하면 백엔드에서 주문을 생성하고 주문번호와 결제 금액을 발급합니다.
2. 프론트엔드가 PG 결제창을 띄워 사용자의 결제 인증을 받습니다.
3. 인증 결과를 백엔드로 전달하면, 백엔드는 저장된 주문 금액과 대조해 검증한 뒤 PG사에 최종 승인을 요청합니다.
4. 승인 결과에 따라 주문·결제 상태(예: `READY` → `PAID` / `FAILED` / `CANCELED`)를 갱신합니다.

## 로컬 개발 환경

### 사전 준비

- Git
- MySQL 8.4
- 프론트엔드/백엔드 런타임 (스택 확정 후 추가)

### 실행

```bash
git clone https://github.com/pm1100tm/payment.git
cd payment

# 백엔드
cd backend
# 실행 방법은 backend/README.md 참고

# 프론트엔드
cd ../frontend
# 실행 방법은 frontend/README.md 참고
```

### 환경 변수

DB 접속 정보, PG 키 등 민감한 값은 각 디렉터리의 `.env` 파일로 관리하며 **저장소에 커밋하지 않습니다.**
필요한 키 목록은 `.env.example`로 공유합니다.

## 협업 규칙

### 브랜치

- `main`: 배포 가능한 안정 버전
- `feature/<기능명>`: 기능 개발
- `fix/<버그명>`: 버그 수정

### 커밋 메시지

```
<type>: <요약>

예) feat: 결제 승인 API 추가
    fix: 결제 금액 검증 오류 수정
    docs: README 업데이트
```

| type       | 의미                   |
| ---------- | ---------------------- |
| `feat`     | 새로운 기능            |
| `fix`      | 버그 수정              |
| `refactor` | 리팩터링               |
| `docs`     | 문서 수정              |
| `test`     | 테스트 추가/수정       |
| `chore`    | 빌드·설정 등 기타 작업 |
